# Private source collector evidence

The collector reads the existing `prospects.created_at` column and keeps its exact value in the encrypted prospect rows. It also retains the exact raw events and watermark from the existing read-only LinkedIn member changelog endpoint. Changelog attempted, completed, and collected times record this collector run; they do not represent provider event time. Provider-generated time is null and upstream freshness is unknown. A null watermark is accepted only for a complete empty changelog response. A missing prospect timestamp stays missing.

Run `PYTHONPATH=src python diagnostics/action-report-private-source-20261002/e2e_private_source.py` from the repository root. The test uses synthetic HTTP responses with the actual clients and OpenSSL CMS roundtrip. Its database mock applies the requested `select` columns, so omitting `created_at` from the collector projection fails the timestamp check. Authorization cases reject missing, duplicate, malformed, wrong-prefix, or malformed member URNs. Changelog cases cover exact event retention, acquisition timestamps, complete empty results, malformed envelopes/events, missing or invalid watermarks, valid scoped pagination, wrong endpoint/query links, malformed next links, and truncation. Each rejected collection must fail before producing ciphertext. Negative cases check their expected error type and message, and injected unrelated collection and encryption faults must fail independently. The evidence file begins each run with `run_status: failed` and changes to `passed` only after all verdicts pass, so an early certificate failure cannot leave stale success evidence. It writes only fixed synthetic verdicts to `e2e-evidence.json`; the temporary certificate, key, and ciphertext are removed when the test ends. The test does not contact live services.
