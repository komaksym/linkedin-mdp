# Combined private action report

The offline combiner reads the existing `invitation-shortlist.json` and `private-dm-actions.json` outputs. It never acquires new source data or changes either upstream decision. The invitation envelope must use schema version 1 and `ready` or `withheld_current_employer_assignments`; the DM planner currently writes direct `reply`, `follow_up`, `first_dm`, `withheld`, and `coverage` fields without a version envelope.

The report keeps invitations, owner-written reply and follow-up reminders, saved researched first-DM drafts, source pointers, date-added provenance, priority factors, source citations, company-cap evidence, exclusions, unknowns, and withheld research separate. Coverage reasons, withheld DM rows, a withheld invitation shortlist, or nonzero invitation withheld counts make the combined status `partial`. Empty action queues are meaningful only for sections whose coverage is complete. An invitation shortlist is capped at 25 distinct exact profiles. A profile cannot appear in conflicting DM action or withheld queues. An empty verified message body is shown as attachment-only with a prompt to inspect its source pointers; the report writes no reply or follow-up text.

Run `scripts/build_combined_action_report.py --invitations <private-json> --dm-actions <private-json> --output-dir <new-dir>`. Both inputs must be regular files private to the owner. The new directory has mode 0700 and contains mode-0600 `combined-action-report.json` and `combined-action-report.txt`. Standard output contains a fixed status line. Unsupported versions, malformed queues, uncited known factors or first-DM drafts, nonfinite numbers, and unsafe text fail before output creation.

For the existing restricted Google Doc, run `scripts/publish_combined_action_report.py --report <combined-action-report.txt>`. It reads only the prepared report. The Google publisher rejects embedded marker tokens, unsafe controls, unpaired surrogates, and bidi overrides or isolates before OAuth. It verifies an editable owner-only document and the marker pair, then changes only the managed region with a revision precondition. It retries one revision conflict after fresh privacy and document preflight. Publication requires configured Google OAuth and document ID. No LinkedIn or Supabase client is imported by either command; sending remains manual.

The synthetic end-to-end harness in `tests/e2e_combined_action_report.py` exercises the offline CLI and mocked Google HTTP boundary. Its evidence artifact records fixed scenario verdicts only. It does not prove fresh live source acquisition or live OAuth delivery.

Repeat the synthetic proof from the repository root with `PYTHONPATH=.:src uv run --extra dev python tests/e2e_combined_action_report.py`. It writes `artifacts/combined-action-report-e2e-evidence.json` after the CLI and simulated Google publication checks.

Failed offline writes clean up only files and the output directory created by that invocation. Foreign files are preserved. Research-queue profiles require canonical LinkedIn profile URLs; explicit null identities remain unknown, while omitted profiles are rejected. The synthetic E2E artifact covers these failure and retry boundaries.
